#### 概述

```sh
# 定义
状态机（State Machine），全称为有限状态自动机（Finite State Machine，简称 FSM），是计算机科学和电子工程中一种用于描述事物状态变化规则的数学计算模型

# 基本要素
1.状态 (State)：系统在某一时刻所处的状况或模式（必须是有限的）。例如自动门的“开启”和“关闭”。
2.事件 (Event / Trigger)：触发状态改变的外部输入或条件。例如“按下开门按钮”或“检测到有人接近”
3.动作 (Action)：状态在转移过程中，系统所执行的具体行为（注意：动作是可选的，有时状态转移不一定伴随动作）。例如“马达开始旋转以打开大门”

# 类型
1.确定性有限状态自动机 (DFA)：对于任何一个特定的状态和输入，其下一个状态都是唯一确定的。
2.非确定性有限状态自动机 (NFA)：在某个状态下收到一个输入，可能会有多种可能的后续状态
# 
在实际工程应用中，通常还会有摩尔型 (Moore)（输出只与当前状态有关）和米利型 (Mealy)（输出与当前状态和输入都有关）的划分

# 特性
# 在没有状态机概念时，程序员通常会使用大量的 if-else 或 switch-case 来控制流程。
# 当业务变复杂时，代码会变成难以维护的“if-else 地狱”
# if else 是事件驱动,状态机是状态驱动
1.业务建模清晰：将复杂的现实规则直接抽象成一张清晰的“状态转换图”，所见即所得
2.防止非法操作（安全性）：状态机天生具备防御性。
3.高扩展性：如果业务增加了一个新状态，只需要在状态机中增加一个节点和几条连线，不需要重构原有的判断逻辑。
```



| 维度         | 传统 `if-else` 设计                            | 状态机设计                                 |
| ------------ | ---------------------------------------------- | ------------------------------------------ |
| **核心视角** | 关注**过程和条件**（如果满足A且不满足B...）    | 关注**状态和边界**（处于A状态，只能做X事） |
| **代码位置** | 逻辑散落在成百上千行条件分支中                 | 规则集中在一张表或独立的状态类中           |
| **可读性**   | 规模变大后成为“面条代码”，极难看懂             | 像说明书一样清晰，直接对应业务状态图       |
| **安全性**   | 容易因为漏写某个 `else` 导致严重的越权非法操作 | 天然防御，不在规则表里的事件直接被拒绝     |
| **扩展性**   | 每加一个状态，要修改所有涉及的 `if-else`       | 只需加个新状态类，或在配置表里加一行       |



#### 代码示例

```py

# =========================================================
# 1. 定义状态、事件（通常用枚举或常量，确保规范）
# =========================================================
class State:
    UNACTIVATED = "未激活"
    NORMAL      = "正常"
    FROZEN      = "冻结"

class Event:
    ACTIVATE = "激活"
    RECHARGE = "充值"
    VIOLATE  = "违规"
    RELEASE  = "解冻"

# =========================================================
# 2. 核心：状态转移矩阵（查表法的灵魂）
#    格式：{ 当前状态: { 事件: (新状态, 执行的动作函数) } }
# =========================================================
def do_activate(): print("执行：发送欢迎短信，发放新手礼包")
def do_recharge(): print("执行：账户加钱，更新vip等级")
def do_freeze():   print("执行：冻结资金，发送站内信警告")
def do_release():  print("执行：解冻账户")

STATE_TRANSITION_TABLE = {
    State.UNACTIVATED: {
        Event.ACTIVATE: (State.NORMAL, do_activate)
    },
    State.NORMAL: {
        Event.RECHARGE: (State.NORMAL, do_recharge), # 状态可以保持不变
        Event.VIOLATE:  (State.FROZEN, do_freeze)
    },
    State.FROZEN: {
        Event.RELEASE:  (State.NORMAL, do_release)
    }
}

# =========================================================
# 3. 通用状态机引擎（一劳永逸，处理任何业务都不需要改这段代码）
# =========================================================
class StateMachine:
    def __init__(self, start_state):
        self.current_state = start_state

    def send_event(self, event):
        # 1. 检查当前状态下，有没有这个事件的定义
        if self.current_state in STATE_TRANSITION_TABLE:
            transitions = STATE_TRANSITION_TABLE[self.current_state]
            
            if event in transitions:
                # 2. 查表：获取下一个状态和要执行的动作
                next_state, action = transitions[event]
                
                print(f"【状态流转】: [{self.current_state}] 收到事件 [{event}] -> 变成 [{next_state}]")
                
                # 3. 执行动作并更新状态
                if action: 
                    action()
                self.current_state = next_state
                return
                
        # 4. 防御性拦截：如果不匹配，说明是非法操作
        print(f"【拦截非法操作】: 当前状态为 [{self.current_state}]，无法响应事件 [{event}]！")

# =========================================================
# 4. 业务调用
# =========================================================
sm = StateMachine(State.UNACTIVATED)

sm.send_event(Event.ACTIVATE) # 成功激活
sm.send_event(Event.RECHARGE) # 成功充值
sm.send_event(Event.ACTIVATE) # 拦截：已经是正常状态了，不能重复激活
sm.send_event(Event.VIOLATE)  # 成功冻结
sm.send_event(Event.RECHARGE) # 拦截：冻结状态下不能充值！

```
