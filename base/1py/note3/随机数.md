

| 特性         | 伪随机数 (PRNG)                      | 真随机数 (TRNG)              |
| ------------ | ------------------------------------ | ---------------------------- |
| **生成源**   | 数学公式 / 算法                      | 物理噪声 / 熵池 / 量子效应   |
| **控制机制** | 由**种子(Seed)**决定，种子同则结果同 | 由**物理规律**决定，不可重现 |
| **速度**     | 极快，计算量小                       | 较慢，依赖硬件收集速度       |
| **安全性**   | 较低（可被破解和预测）               | 极高（不可预测）             |
| **常见应用** | 游戏、数据模拟、普通算法测试         | 加密密钥、安全认证、数字签名 |

```sh
# 抛硬币：

收集'键盘敲击间隔'、'鼠标轨迹'、'热效应'。这些在宏观物理上也是确定的（由神经电信号、肌肉惯性决定）。之所以无法预测，不是因为它们在宇宙中是真随机，而是因为拿不到这些极其微观的'物理上下文数据'。被认为是'真随机'；但在宇宙的物理规律看来，它只是极其复杂的'伪随机'

假设有一个铀原子，它可能在下一秒衰变，也可能在100年后衰变。量子力学证明，没有任何物理公式能预测它具体在哪个精确纳秒衰变。它在这一秒衰变的概率是纯粹的、本质的、没有任何隐藏变量控制的真随机
# 电子双缝干涉、光子偏振
```

```sh
# 伪随机数的安全性

# 案例:远程网络攻击中的“时间碰撞”
1.棋牌游戏网站，其发牌的随机数种子是 srand(time(NULL))（精确到秒）或者更高精度的纳秒时间戳
2.黑客写好一个外挂脚本。在黑客点击“加入游戏”的瞬间，脚本会记录下当前黑客电脑的本地时间戳
3.服务器收到请求，读取服务器的系统时间（比如 1711812345.678901 秒），以此为种子生成了一副牌
4.黑客和服务器之间虽然有网络延迟，但这个延迟通常在几十毫秒以内。黑客的脚本只需要在自身时间戳的 ±100毫秒（即包含几十万到几百万纳秒） 范围内进行暴力穷举
5.黑客的电脑性能极高，几毫秒内就能把这几百万个种子全部模拟一遍。只要发现其中某一个种子生成的牌和黑客手里发到的牌一模一样，黑客就瞬间锁定了服务器的精准纳秒种子。接下来，服务器后续会发什么牌，黑客一清二楚

# 案例:逆向工程与状态克隆
1.Python、JavaScript、Java 默认使用的 梅森旋转算法
	-- 该算法在内存中维护了一个拥有 624个整数的状态机。它每次吐出随机数，其实就是在滚动这个状态机
2.黑客不需要管你是哪一纳秒启动的。他只需要连续收集你程序产生的 624个随机数输出
3.通过这624个数字，利用线性代数方程组，黑客可以在几毫秒内逆向推导出整个算法当前在内存中的完整状态。一旦状态被复制，算法接下来会吐出的第625个、第1000个、第10000个数字，黑客都能提前知道

# 真实案例:著名的“德州扑克”洗牌漏洞(1999)
1.德州扑克软件使用 Delphi 语言的 Randomize() 函数。该函数以自午夜以来的毫秒数作为种子
	-- 1天有 86,400,000 毫秒，这意味着一整天只有 8600 万种可能的洗牌结果
2.黑客通过追踪自己手里的 5 张牌，配合网络延迟估算，在几秒钟内就从 8600 万种组合中锁定了解析解。最终，黑客可以实时看到场上所有对手的底牌，以及即将发出的公共牌，轻松赢走大笔资金

# 真实案例:加密货币钱包私钥被盗 (2014年)
1.早期 Android 比特币钱包由于 Java 的 SecureRandom 底层在特定系统版本上出现了致命 Bug，导致生成的随机数种子高度可预测（甚至在某些纳秒范围内重复）
2.黑客通过区块链上的公开交易，逆向分析出生成私钥的随机数序列
	-- 由于种子范围极小，黑客暴力跑完所有可能性，直接猜出了大量用户的私钥，洗劫了数百万美元的资产
```
