

```sh
# 代码逻辑
1.cpu执行代码,申请数据写入内存
2.cpu调用显卡api,显存申请数据空间
3.cpu执行发送编译的gpu的算法指令,到显存指令缓冲区
4.显卡接管执行
	-- 显卡成千上万个核心,组成不同的车间
	-- 每个车间包含一定数量的核心(如128个核心)
	-- 算法指令同步到每个车间的指令发射器
	-- 车间需要的整块数据同步到车间的硬件单元
	-- 指令发射,数据传递,车间的核心同时通电执行
5.最终执行结果,返回cpu内存
```



Python 显式调用英伟达最底层的 CUDA Driver API（通过 `ctypes`）

简单的最邻近插值图片放大代码:

```py
import ctypes
import math

# ==========================================
# 0. 模拟图片数据 (假设为 2x2 的单通道灰度图，放大到 4x4)
# ==========================================
SRC_H, SRC_W = 2, 2
DST_H, DST_W = 4, 4

# CPU 视角：原图 4 个像素点 (10, 20, 30, 40)
src_image_data = (ctypes.c_ubyte * 4)(10, 20, 30, 40)

# ==========================================
# 1. 初始化 GPU 硬件驱动 (Driver API)
# ==========================================
# 硬件动作：加载 libcuda.so/cuda.dll 驱动，CPU 向 GPU 发送硬复位与初始化信号
cuda = ctypes.CDLL("libcuda.so") # Windows 下为 "nvcuda.dll"
cuda.cuInit(0)

# 硬件动作：获取第 0 块物理显卡的句柄
device = ctypes.c_int()
cuda.cuDeviceGet(ctypes.byref(device), 0)

# 硬件动作：在 GPU 芯片上创建一个“上下文空间”（给此进程分配独立的显存管理和指令调度队列）
context = ctypes.c_void_p()
cuda.cuCtxCreate(ctypes.byref(context), 0, device)

# ==========================================
# 2. 内存申请阶段 (CPU 内存 与 GPU 显存)
# ==========================================

# 【CPU 端内存申请】
# 硬件动作：CPU 操作系统在主内存(RAM)中开辟一块 16 字节的连续缓冲区，用于存放放大后的图片
# 这块内存受 CPU 的 MMU（内存管理单元）保护
cpu_dst_buffer = (ctypes.c_ubyte * (DST_H * DST_W))()

# 【GPU 端显存申请】
# 硬件动作：显卡控制器在 GPU 物理显存(VRAM)中，根据分配算法锁定了两块物理地址空间
# 此时显存芯片（GDDR6/HBM）的行/列地址被激活并记录在 GPU 内存映射表中
gpu_src_ptr = ctypes.c_void_p()
gpu_dst_ptr = ctypes.c_void_p()
cuda.cuMemAlloc(ctypes.byref(gpu_src_ptr), SRC_H * SRC_W) # 申请 4 字节原图显存
cuda.cuMemAlloc(ctypes.byref(gpu_dst_ptr), DST_H * DST_W) # 申请 16 字节目标图显存

# ==========================================
# 3. 数据搬运阶段 (Host to Device)
# ==========================================
# 硬件动作：CPU 触发 DMA（直接内存访问）控制器。
# 数据不经过 CPU 核心，直接通过主板上的 PCIe 总线插槽，以流水线方式强行灌入显卡的显存芯片中
cuda.cuMemcpyHtoD(gpu_src_ptr, ctypes.byref(src_image_data), SRC_H * SRC_W)

# ==========================================
# 4. 算法指令代码 (编译 GPU 机器码)
# ==========================================
# 这是 CUDA C 语言写的“最邻近插值”核心算法。
# 注意：里面没有 CPU 常见的 `for` 循环！
cuda_kernel_source = f"""
extern "C" __global__ void nearest_neighbor(unsigned char* src, unsigned char* dst) {{
    // 硬件动作：每个 GPU 核心执行时，会根据自己所在的硬件硬件编号(ThreadIdx)算出自己负责的像素横纵坐标
    int x_dst = blockIdx.x * blockDim.x + threadIdx.x;
    int y_dst = blockIdx.y * blockDim.y + threadIdx.y;

    // 边界检查：如果线程编号超出了目标图片的 4x4 范围，该核心直接休眠
    if (x_dst < {DST_W} && y_dst < {DST_H}) {{
        // 核心计算：计算缩放比例
        float scale_x = {(float)SRC_W / DST_W};
        float scale_y = {(float)SRC_H / DST_H};

        // 核心计算：最邻近映射取整
        int x_src = (int)(x_dst * scale_x);
        int y_src = (int)(y_dst * scale_y);

        // 核心动作：一维线性索引转换
        int dst_idx = y_dst * {DST_W} + x_dst;
        int src_idx = y_src * {SRC_W} + x_src;

        // 硬件动作：核心发出读写指令，从原图显存地址读出 1 字节，写入目标显存地址
        dst[dst_idx] = src[src_idx];
    }}
}}
"""

# 模拟底层编译（实际工程中由 NVRTC 库将文本转为 GPU 能听懂的 PTX 机器码汇编）
# 硬件动作：机器码指令通过 PCIe 发送，并写入到 GPU 的“指令缓存 (Instruction Cache)”中
# 假设我们已经得到了编译好的模块句柄 `module` 和函数句柄 `kernel_func`
module = ctypes.c_void_p()
kernel_func = ctypes.c_void_p()
# 注：此处的编译和加载细节在纯 Python 中需调用 nvrtc 动态库，为保持核心逻辑清晰，此处指代其硬件加载行为
# cuda.cuModuleLoadData(ctypes.byref(module), ptx_code)
# cuda.cuModuleGetFunction(ctypes.byref(kernel_func), module, "nearest_neighbor")

# ==========================================
# 5. GPU 接管与并行执行阶段 (Launch Kernel)
# ==========================================
# 规划：目标是 4x4 图片，我们配置一个 4x4 的二维线程网格（Grid）
# 硬件动作：CPU 填写一组“任务启动卡”（网格大小、显存指针参数），将其推入 PCIe 的命令环形缓冲区（Command Queue）
# 随后，CPU 的执行线程转入等待，GPU 的硬件调度器（Hardware Scheduler）正式接管控制权。

# GPU 内部硬件流水线被激活：
# 1. 调度器看到我们需要 16 个线程，它将这 16 个线程打包分配给 GPU 的 SM（流式多处理器）。
# 2. 16 个物理核心（ALU）的寄存器被分别注入了其对应的坐标：核心1(0,0), 核心2(1,0)...核心16(3,3)。
# 3. SM 的控制单元发出“单指令”：所有核心同时执行坐标换算、同时发出显存请求。
# 4. 显存控制器将 16 个核心的读取请求“合并”为单次高效的主体访问，几纳秒内完成 16 个像素的缩放和写入。
"""
cuda.cuLaunchKernel(
    kernel_func, 
    1, 1, 1,        # Grid 维度 (1个大区块)
    4, 4, 1,        # Block 维度 (每个区块内 4x4=16 个并行线程)
    0, None,        # 共享内存大小及流
    ctypes.byref(gpu_src_ptr, gpu_dst_ptr), # 将两个显存的物理地址作为参数传给 GPU 寄存器
    None
)
"""

# ==========================================
# 6. 数据回收与内存释放阶段 (Device to Host)
# ==========================================
# 硬件动作：CPU 发出指令，等待 GPU 发出“计算完毕”的硬件中断信号。
# 收到信号后，CPU 再次调动 DMA，通过 PCIe 总线将 16 字节的放大结果从显存抓回主内存 `cpu_dst_buffer`
cuda.cuMemcpyDtoH(ctypes.byref(cpu_dst_buffer), gpu_dst_ptr, DST_H * DST_W)

# 硬件动作：显卡控制器擦除内存映射表，释放这两块显存物理空间供其他程序使用
cuda.cuMemFree(gpu_src_ptr)
cuda.cuMemFree(gpu_dst_ptr)

# 硬件动作：销毁 GPU 上下文，断开与显卡的控制连接
cuda.cuCtxDestroy(context)

# 输出结果验证
print("CPU 收到 GPU 硬件加速缩放后的像素矩阵:")
print(list(cpu_dst_buffer))

```
