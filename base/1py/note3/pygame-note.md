

#### 控制帧率原理

Pygame 的 `pygame.time.Clock().tick(60)` 底层原理

```sh
假如为了实现完美的 60 帧稳定画面，Pygame（基于 SDL）在底层进行了一套“高精度时钟提升 + 动态时间差补”的复合操作。
当你在游戏循环里写下 clock.tick(60) 时，底层的 C 语言库实际上执行了以下硬核流程：
# 1. 强制拔高操作系统的硬件精度
	在 pygame.init() 阶段，底层 C 代码会调用 Windows 专属的底层命令 timeBeginPeriod(1)。
	-- 这个命令的作用是：强行将 Windows 默认的 15.6 毫秒时钟精度强行提升到 1 毫秒！
	-- 这样，操作系统的大管家就会变得极其敏锐，每隔 1 毫秒就会检查一次线程。
# 2.精准计算“这一帧我已经耗费了多少时间”
	每次 tick(60) 被调用时，底层会先用高精度的 CPU 计数器（如 QueryPerformanceCounter，精度可达微秒级）记录当前时间，并减去上一帧结束的时间。
	-- 目标：60 帧意味着每帧目标时间是 16.67 毫秒。
	-- 假设：经过底层高精度计算，发现你的 Python 游戏逻辑和画图代码刚才已经跑了 6 毫秒。
# 3.动态睡觉（精准休眠）
	既然已经用掉了 6 毫秒，为了凑齐 16.67 毫秒，这一帧只需要再睡 16.67 - 6 = 10.67 毫秒。
	-- 此时底层会调用 SDL 的高精度休眠函数，让线程精准睡下 10 毫秒。
# 4. 最后的“自旋锁（Busy-Wait）”冲刺
	当线程休眠 10 毫秒醒来后，时间可能到了 16.1 毫秒，距离 16.67 毫秒还差最后的 0.57 毫秒。
	-- 这时 Pygame 知道：如果再调用一次 sleep，操作系统一定会迟到。
	-- 于是底层使出绝招——死循环自旋（While Loop 盲等）：让 CPU 在这最后的 0.57 毫秒里疯狂空转死等，用 100% 的 CPU 火力死死卡住时间，直到高精度时钟跳到 16.67 毫秒的那一微秒，立刻放行！
```

#### flip() 和 update()区别

```sh
#显示器只盯着前缓冲区（Front Buffer）看。
而 flip() 和 update() 的本质区别，在于它们如何把“后缓冲区（Back Buffer）”画好的新内容，同步给前缓冲区

# pygame.display.flip()：全盘颠倒（指针切换）
底层:它直接在显卡里交换了前、后缓冲区的内存地址指针。

# pygame.display.update(rect)：局部搬运（像素拷贝）	#没有硬件加速的过去的老方法
底层动作： 它不交换前后台的指针。前台依然是前台，后台依然是后台。
底层 C 语言会跑去后缓冲区，找到你指定的那个小方块（Rect），比如一个 32x32 的小球，然后执行 memcpy（内存拷贝），只把这 32x32 的像素数据，强行覆盖到前缓冲区的对应位置上。

#----------
# update() 是没有硬件加速的过去的老方法
# update() 不带参数,则与 flip() 一样
```
