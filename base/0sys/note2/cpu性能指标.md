#### cpu

```sh
# 运行原理
-- 通电后,cpu 就无脑一直运行,不停的读取指令寄存器(PC)的地址执行
-- 地址可能是程序地址,也可能是空闲进程的地址

# 中断
-- 原理: 触发修改 指令寄存器地址 ,促使 cpu 执行中断处的代码
-- 操作系统通过 '中断' 控制cpu
-- 例如: 系统多任务也是由时钟中断控制

# 时钟周期
-- cpu运行度量单位: CPU 晶振（Oscillator）在某段人类时间里，一共跳动了多少次。
-- 如果 CPU 是 3.0 GHz，意味着它每秒钟的内部时钟会跳动 30 亿次（即 30 亿个时钟周期）。
-- 举例:
	做一次简单的加法（ADD），CPU 只需要 1 个时钟周期
	去内存里读取一个数据（MOV 触发内存延迟），CPU 硬件需要原地傻等 200 个时钟周期。
	
# 时钟中断
-- 主板定时器芯片,每隔固定毫秒发出的电信号
-- 判断时钟周期,系统根据分配的时间片 调度任务

# 空闲进程
-- 本质是一段死循环代码, 让 CPU 核心进入低功耗的“睡眠挂起”状态，直到下一个硬件 '时钟信号' 把它唤醒
-- 系统任务执行完后,并且操作系统队列无内容,调度代码就会设置地址,让cpu进入空闲进程

# 硬件中断
-- 解释: 独立的硬件芯片,强制设置 指令地址寄存器的值,促使 cpu 前往这个地址执行新的代码
-- 包括: 时钟中断(定时发送),键盘鼠标等主动触发的中断
-- 举例: cpu在空闲进程时,必须发起硬件中断,才能迫使cpu执行其他程序
-- 案例: 
	系统任务和cpu空闲进程的切换:
	1.任务执行时间片过后,cpu进入空闲进程
	2.时钟中断信号定时发送电信号,促使cpu物理中断,去固定的寄存器地址,读取中断向量表,
	从里面找对应中断的指令地址执行	#即 操作系统的调度代码 地址,(该地址在开机的时候,由bios引导填进中断向量表)
	

# 软件中断
-- 解释: 任务或程序执行完后,操作系统调度代码通过软中断,设置空闲进程地址,cpu进入空闲进程

```

**cpu利用率** 

```sh
# cpu总运行时间
-- 操作系统（OS）会设定一个固定的观察周期。例如每隔 10 毫秒（ms）统计一次。在这 10 毫秒内，这颗 3.0 GHz 的 CPU 一共拥有 30,000,000 个时钟周期。这就是总运行时间。

# 定时器/计数器
-- 独立硬件芯片, 定时向 cpu 发送 时钟中断
-- 比如每隔 10 毫秒，这个定时器芯片就会向 CPU 发送一个时钟信号
-- 通过定时器可计算出 空闲进程时间

# cpu 利用率
-- cpu利用率 = ((总运行时间 - 空闲进程时间)/总运行时间) x 100%


# 详细解释
-- 例如单核cpu,每秒处理100次请求 (qps),的计算过程:
   1.假设 CPU 的时钟频率是 3.0 GHz（每毫秒有 300 万个时钟周期）,
   2.最简单的 Web 请求,软件代码大约需要执行 30,000 条汇编指令（包括网卡驱动收包、解析 HTTP 协议头、查找网页文件、再通过网卡发回去）。
   3.平均执行 1 条指令需要 2 个时钟周期, 处理 1 次请求 = 消耗 60,000 个时钟周期
   4.除去其他消耗,在第 1 毫秒内，CPU 成功处理完了 45 次请求,270万时钟周期,此时cpu利用率: 100%
   5.第2毫秒,处理45个请求,cpu利用率: 100%
   6.第3毫秒,处理10个请求,花费60万个时钟周期,240万时钟周期空闲进程,此时cpu利用率:
   		((300万-240万)/300万) x 100% = 20%
   
```
