#### utf编码

```sh
#utf-8
变长编码,使用 1 到 4 个字节来表示一个字符
兼容 ASCII： 所有的英文字母和数字只占 1 字节	#与 ASCII 码完全相同
绝大多数中文字符占用 3 字节
字节流中有特殊的标记位（如 10xxxxxx），如果传输中丢了一个字节，系统能快速定位下一个字符的开始，不会导致整段乱码。
UTF-8 是以单字节为单位处理的，不存在大端小端的问题

通过字节最头部的几个比特（前缀位）来声明
0xxxxxxx	#单字节字符,凡是 0 开头的，都是标准的 ASCII 码。
110xxxxx	#2字节字符
1110xxxx	#3字节字符, 绝大多数中文在此
11110xxx	#4字节字符, 如 Emoji 或生僻字
10xxxxxx	#这是一个字符中间的片段，不能单独存在, 剩下的 6 位才是真正存储字符数据的有效信息


#utf-16
使用 2 或 4 个字节
Windows 内部内核、Java、JavaScript 内存中的字符串默认都是 UTF-16
绝大多数中文在 UTF-16 里只占 2 字节
需要 BOM（字节顺序标记）来区分是 LE（小端序）还是 BE（大端序）

#utf-32
定长编码, 每个字符强行占用 4 字节	#即使是一个空格也要占 4 字节
计算字符串长度或跳转到第 n 个字符只需 O(1) 时间，无需遍历。适用于需极高性能处理,如科学计算

#永远优先选择 UTF-8（默认不带 BOM）

#关于BOM
BOM 是位于文本文件最开头的一串不可见字符
告诉编辑器这个文件是 UTF-8、UTF-16 还是 UTF-32
在 16 位或 32 位编码中，告诉系统数据读取是从左往右（大端序）还是从右往左（小端序）
```

#### 可执行文件结构

```sh
#无论是在 Windows（PE 格式）还是 Linux（ELF 格式）中，二进制可执行文件的结构通常都遵循一种分层布局，主要由“头信息”和“数据节”组成

#文件头 (File Header)
	魔数 (Magic Number)：用于标识文件格式（例如 PE 文件以 MZ 开头，ELF 文件以 0x7F 'ELF' 开头）
	目标架构：说明该程序是为哪种 CPU 运行设计的（如 x86、x64 或 ARM）
	入口点 (Entry Point)：记录程序执行的第一条指令在内存中的地址
	节表索引：描述文件中各个“节”（Section）的大小和位置偏移。
#代码节 (Code Section / .text)
	该区域通常被标记为只读和可执行，以防止程序在运行时意外修改自己的代码。
#数据节 (Data Sections)
	已初始化数据 (.data)：存放有初始值的全局变量和静态变量
	未初始化数据 (.bss)：为没有初始值的全局变量预留空间，在磁盘上不占空间，仅在加载到内存时分配。
	只读数据 (.rdata / .rodata)：存放常量、字符串字面量等不可修改的数据。
#符号与导入/导出表 (Symbol & Import/Export Tables)
	导入表 (Import Table / .idata)：列出程序运行所需的外部 DLL 或共享库及其函数
	导出表 (Export Table / .edata)：如果该文件是库文件（如 .dll 或 .so），则列出它提供给其他程序使用的函数。
#资源节 (Resource Section / .rsrc)
	主要存在于 Windows 程序中，包含程序图标、菜单、对话框界面、字符串表甚至嵌入的图片或字体文件。
#重定位表 (Relocation Table / .reloc)
	当程序无法加载到其首选的内存地址时，操作系统利用此表中的信息修正代码中的硬编码地址，确保程序在内存的任何位置都能正常运行。
```



#### 进制转换思路

```sh
#示例:10进制转2进制
#假设数字num=101
步骤a. num%2=d1 #得到最低位的进制d1	# 这个应该不难理解
步骤b. 先num/2=num2,再执行:num2%2=d2 #d2与d1合并,此时得出最低位的2个进制=>d2d1	
重复执行步骤b. 得出的结果放在之前合并的进制前面

#原理:
第1步通过模运算得出最低位进制,应该容易理解
第2步,为什么要先除2呢,拆解如下:(假设数字为101对应101个苹果)
	a.求最低位进制时,最小单位是1,数字101分成101份,按2进制就是,每2份划到一起,最后只有1个苹果剩余,(101%2=1)
	剩余那个不管了,还剩100个苹果
	b.求倒数第2位进制时,此时最小单位是2, (进制每前面1位,最小单位都是后面1位的进制倍数)
	此时得把每2个苹果绑定在一起(这里用黑色袋子装起来)当作最小单位,结果就是50份,
	然后这50份求低位进制,2份放一起,剩余0份,(50%2=0)
	c.继续求倒数第3位进制,此时最小单位是4(2^2),即50份再每2份放一起(用黑色袋子装起来),结果是25份,
	然后这25份求低位进制,2份放一起,剩余1份,(25%2=1)
	...
	重复,每进一位就x2当作最小单位(用新袋子把之前的2个袋子装进来)
	
#原理2:
	求哪一位的进制,比如i位,就是(101/(2^(i-1)))%2
	即2^(i-1)为最小单位
	
```

#### https长连接

```sh
#在 HTTP/1.1 中，长连接是默认开启的
客户端在请求头中携带 Connection: keep-alive
其核心目标是避免频繁进行高昂成本的 TCP 三次握手和 TLS 安全握手

#心跳探测
#当连接长时间没有数据往来时，操作系统内核会发送微小的探测报文（Keepalive Probe）给对方
1.许多 Linux 服务器的默认 tcp_keepalive_time 依然是 2 小时。这意味着如果你只发呆 10 分钟，可能还没触发系统级的探针
2.为了提高效率，很多网站服务器（如 Nginx）会把应用层的 Keep-alive 超时设为 60~120 秒。这时候，如果你一两分钟没操作，服务器可能直接根据应用层规则断开连接，而不是等待底层的 TCP 探针去探测
```

#### 数字签名原理

```sh
1.权威证书机构提供私钥,公钥,私钥严格内部保存,公钥下发给操作系统预装
2.软件发布时,向证书机构请求签名,证书机构用私钥对文件指纹(哈希值)进行签名,生成签名
3.软件发布者将签名数据保存在软件PE头或尾部
4.软件安装时,操作系统用公钥解密签名数据,解密后再比对文件指纹,完全一致,则说明签名合法

#私钥保护级别
1.物理隔离： 私钥保存在不联网的硬件加密模块（HSM）中
2.这些设备通常存放在带生物识别（指纹、视网膜）、全天候监控、甚至防核打击的地下库房里
3.启用一次私钥需要多名高管同时插入不同的物理钥匙
4.顶尖审计公司每年会对这些机构进行 WebTrust 审计。如果审计不合格，微软/谷歌会立即从系统中删除这个根证书，该机构就会直接破产
```



#### 文件加密原理

```sh
1.密钥派生： 软件会将你输入的“明文密码”（如 123456）通过复杂的数学运算（如 PBKDF2 或 Argon2 算法）转换成一段超长的二进制数据（即密钥）
2.数据加密： 软件使用这个密钥配合加密算法（如 AES-256）对文件内容进行打乱。
3.哈希验证码： 为了能在你下次输入密码时判断对错，软件会在文件头存一段哈希值。当你再次输入密码，软件计算新输入的哈希并与文件头里的哈希对比，一致则开门。
```

#### 关于hash碰撞

```sh
#鸽巢原理(数学基础)
	#主流的 SHA-256 算法中，输出空间是 2^256
	1.这个数字有多大？它大约是 \(10^{77}\)，而整个可见宇宙中的原子数量估计也才 \(10^{80}\)
	2.通过极大的分母，让两个随机输入撞在一起的概率变得微乎其微。即使你每秒生成 10 亿个 Hash，也要连续跑几十亿年才可能遇到一次随机碰撞
	
#雪崩效应（Avalanche Effect）
	Hash 函数内部通过复杂的布尔运算（异或、位移、与非）确保了输入极小的变化都会导致输出剧烈的变动。
```



#### 小数存入计算机的过程

```sh
#通过不断对折实现:
2^-1 = 0.5		#二进制: 0.1
2^-2 = 0.25		#二进制: 0.01
...
#过程:
假如 0.77 存入内存:
1. 和0.5比,存1,剩 0.27
2. 和0.25比,存1,剩 0.02
3. 和0.125比,存0,剩 0.02
4. 和0.0625比,存0.剩 0.02
...
一直往下直到达到浮点精度
#问题:
计算机还没存入0.77, 那0.77是怎么和0.5比大小的呢
软件算法层面的计算(编译器做了翻译):
1.识别字符串:"0","7","7"
2.转成大整数:把0.77变成77,并记住它缩小100倍
3.计算77是否大于50
	 27是否大于25
	 2是否大于12.5	#实际上应该是20和125)
	 ....
计算完这个过程,才把结果存入内存,这个结果就是二进制形式的小数表示

#总结:
1.过软件的翻译阶段把小数转换成二进制形式放入内存 #翻译过程慢
2.用二进制形式在电路里跑加减乘除运算			   #二进制后的计算很快
```

#### 字节流字符流

```sh
#字节流
1. 最小单位：1 字节 (8 bits)
2. 处理二进制数据,它不对数据进行编码处理，只是原封不动地搬运 0 和 1
========================
#字符流
1. 最小单位：1 个字符（长度取决于编码，如 UTF-8 中一个汉字占 3 字节）
2. 处理纯文本数据,它会自动处理字符编码,它会把读取到的字节根据编码表（如 UTF-8, GBK）翻译成人类能看懂的字符
-----------
#字符流读取:
1.从底层字节流抓取一大块原始字节(如1024字节),放入缓冲区
2.字符流阅读器根据编码类型长度开始扫描
#字符流写入:
1.编码转换:对写入字符查表找到对应字节
2.检查:如字符在编码表不存在,处理替换符号
3.一般是行缓存逻辑,如遇到\n写入
```

#### 序列化

```sh
序列化 (Serialization) 就是把内存里的“活对象”变成“木乃伊”（字节流/字符串），以便于存储或传输；反序列化 (Deserialization) 就是把“木乃伊”重新注魂，变回内存里可以运行的“活对象”。

不同语言序列化底层逻辑不同,不能通用
但是可以使用通用数据格式实现通用,比如使用json序列化等
```
