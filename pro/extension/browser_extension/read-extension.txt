浏览器插件:
	环境: chrome

	基础结构:
		配置: manifest.json
		弹出页: popup.html
		内容脚本: content.js
		后台脚本: background.js

	跨域说明:
		同源策略,跨域限制
		网页允许跨域的标签: script, link, img
		
		关于跨域的blob链接:
			blob连接 (生命周期: 当前上下文会话)
			blob链接绑定到它的创建源,如跨域的blob:
				控制台注入无法fetch					//属于沙箱环境
				浏览器扩展内容脚本也无法fetch		//属于隔离环境
				网页注入js							//等同于当前页面原生js,受限于当前页面同源策略 (但是,浏览器禁止页面 JS 修改“安全敏感请求头”)
				后台脚本可以fetch					// manifest.json中 host_permissions 声明,即可跨域
		补充:
			chrome.downloads.download ,api 受同源策略限制,无法跨域
			后台脚本无法使用 window.URL.createObjectURL(blob) 方式创建临时url 进行下载
			非同源url,a链接只能打开,无法下载

	总结下载思路:
		1.遍历页面video元素,给每个视频元素添加下载按钮
		2.下载按钮点击:
			开启后台脚本网络请求监听(监听的视频地址)
			同时触发视频重新下载方法 video.load()
			监听到视频加载完成(2s后没有监听到新的流量):
				关闭网络监听
				同时获取监听的视频url,发送到内容脚本
				创建下载面板,根据视频url,创建下载子按钮
				点击具体下载按钮,发送下载事件到后台脚本
				后台脚本访问 python 服务端,服务端执行下载
				使用 ffmpeg 将下载的数据合并,返回给前端
				后台脚本拿到数据,生成blob,再交给chrome.downloads.download下载

	注意:后台 background.js运行在独立的控制台,在扩展管理界面点击Servivce_Worker打开
		 跨域默认不发送cookie,除非指定
		后台脚本发送网络请求,如fetch时,由于浏览器安全限制,会把headers里面的referer删除,请注意!

		 安装插件时,注意权限:
		 	不要让插件"读取所有网站数据"(意味着可以读取本地数据,storage,cookie,session等)
			不要选"读取文件网址" (读取本地文件)

	note:
		关于内容脚本和后台脚本:
			内容脚本:
				与当前网页实例绑定,每打开一个网页就会注入一个内容脚本实例,关闭网页则销毁
				只能操作storage.local,不能操作stoarge.session
			后台脚本:
				单例,全局只有一份
				其全局变量所有网页共用
				在闲置时(几十秒到几分钟不等)会重启,变量重置		#所以后台脚本的全局变量不可靠
				能操作storage.local,能操作stoarge.session

		关于storage:
			storage存储的数据,所有网页共享
			不建议往storage.local存数据,会触发磁盘读写,速度慢 (除非确实需要持久化的数据,浏览器关闭也要保存)
			建议使用stoarge.session内存级存储,浏览器关闭数据丢失
				建议根据网页tabid存储数据,以区分不同的网页

		关于下载时创建的临时链接的回收问题:
			const tmp_url = window.URL.createObjectURL(blob)
			应该设置极短延时,确保点击事件在主线程处理完毕后(即交给浏览器下载进程后),再回收
			只有回收了这个 tmp_url 引用,gc才会回收blob,否则blob一直占据内存,会导致内存飙升,越来越卡(直到关闭或刷新当前页面)

		关于内容脚本和后台脚本通信:
			典型的跨进程通信（IPC）: 浏览器将数据序列化（通常转成 JSON 字符串），通过底层的进程间通信管道发送，接收端再反序列化
			实时性： 极高（毫秒级）。对于普通指令，延迟通常在 1-5ms 左右，用户完全感知不到。
			短连接 (sendMessage)
			长连接 (connect)

		后台脚本给内容脚本发1次消息,为什么内容脚本会打印2次?

			"content_scripts" 里的 "all_frames" 写成了true,修改如下:
			"all_frames": false
