扩展:单页面(spa)应用
	单页面应用,地址跳转时不会刷新(底层阻止了浏览器的重新加载行为),由js框架接管,只是执行dom操作
	不会发生页面上下文资源的销毁和重建,所以性能比传统网页快
	常见需要回收的情况:
		定时器（Timer）			# 最常见的内存泄漏来源 clearInterval(timerId)
		全局事件监听器			# 在 window、body 或 document 上绑定了事件（如 resize、scroll、mousemove）
		WebSocket 与长连接		# socket.close()
		闭包引用的外部变量
		Canvas 与 WebGL 上下文	# 大量的 Canvas 画布或 WebGL 纹理
		第三方库实例			# 初始化了 ECharts 图表、富文本编辑器（Quill/TinyMCE）、地图（Leaflet/Google Maps）等
		未处理的 Promise / 挂起的请求

监听器和事件循环大致概述:
	事件循环:调度员			# 一个线程只能有一个事件循环
	监听器:具体要做的事		# 一段代码
	主线程运行时,注册监听器:将该监听器代码绑定到信号表 (即检测到"约定信号"时,执行该监听器代码)
	主线程的事件循环运行,检测信号表,有信号则运行对应监听器代码,否则申请挂起(让出cpu)
	其他线程发送信号消息时,(浏览器)内核将"约定的信号"写入信号表,并申请系统内核恢复主线程运行(执行事件循环)

blob地址播放原理:
	1.视频页面初始化时js脚本生成blob空对象,将其地址对应url给到页面<video元素的src	#开始没数据,显示加载中
		当 <video> 标签加载了这个 blob: 地址后，会触发一个事件叫 sourceopen
		JS 监听到这个事件后,内部创建数据通道（通道 A：专门接收视频数据,通道 B：专门接收音频数据)
	2.js脚本根据自定义逻辑算法,生成真实视频分片url,fetch或XMLHttpRequest访问后端获取数据,放入数据通道
	3.浏览器底层解码器发现通道有数据,开始解码,播放
	4.继续步骤2 (已播放的分片,内存定期自动清理)

浏览器断点调试:
	F12->network,找到页面html的document请求,右键->open in sources panel
	打某个位置打断点,刷新页面
		step over	#单步跳过 	(执行下一行)
		step into 	#单步进入	(进入当前行调用的内部执行)
		step out 	#单步返回	(一键执行完当前函数,返回上一层往下执行)
	给请求打断点,比如某个fetch请求url包含字符串"xxx":
		在sources面板,右侧 XHR/fetch breakpoints,点+号,输入"xxx"

关于youtube捕获的url无法请求:
	原因整理:
		1.http指纹,浏览器的http协议,和python的requests 不一致
		2.TLS握手特征,同理,浏览器的TLS握手阶段和requests 有差异
		3.动态参数,url请求一次即失效 	#(重放攻击)
		4.其他,headers大小写等
	逆向思路:
		先用抓包发现网络层的区别（如 HTTP 版本、TLS 指纹）。
		再用 DevTools 断点 摸清应用层的算法（如 sig、n 的计算）。
		最后用 Hook 审计 揪出系统硬件层的校验（如 PO Token）。
